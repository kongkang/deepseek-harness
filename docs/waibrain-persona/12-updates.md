## 第二部分（#650–#1089，09-17 白天）：工程落地层

本段是全对话最接近实施的段落，从「AI 乱干活」的挫败出发，落到授权概念与 DSH 落地路径。

### 已合入正文的需求

- **授权识别**（→ [04-workers.md](04-workers.md) WRK-5）：「AI 总是过度地去思考、过度地去干活儿」（#658）、「没问明白，做的东西不是我想要的」（#666）；行动倾向是独立变量（#708，模型存在 intrinsic over-calling bias）；「目标明确、范围明确、授权明确才执行……不是意图识别，而是授权识别」（#714）。
- **评价标准修正**（→ [10-emotion-relations.md](10-emotion-relations.md)）：「一致性优先于预测率」（#788/#791/#831）——可买可不买时买或不买都对，「除非说话跟行为完全违背」才算问题；据此否定行为预测类研究的价值。
- **表现层定位收紧**（→ [02-architecture.md](02-architecture.md)）：主对话「只负责说不说话以及怎么表达。它不能重，重了反应就变慢」（#836）；是表演层、不思考的小模型（#858–#860）；子对话之间的协调下沉第二层（事件总线+订阅、扁平不从属，#836–#839）。

### 记录在本篇的机制（未合入正文）

- **原子 Agent spec**（#961/#968）：主/子对话是同一最小 Agent 的不同实例，六要素——id、模型、system prompt、tools、skills、独立 session；主=快模型+表达型 prompt+几乎无工具，子=强模型+思考型 prompt。落地选 DSH 插件框架，只用框架不继承编排逻辑（#953/#960）。
- **公共时间线**（#987–#1001，💬 提案、用户未反对）：子对话每轮只看实际发生过的话（用户+主对话说出口的）+ 少量私有标签（如"我关注什么"），丢弃上轮私有推理，除非被提升为共享结构化状态——防分支漂移（「越来越偏……那个分支就变得没有用了」#987）。
- **缓存感知架构**（#1002–#1042）：分支独立缓存链使 1+N 成本线性爆炸；方案——共享 system/tools/公共历史前缀，分支差异用会话中途 System 追加（DeepSeek V4.1 Flash 原生支持中途 System、磁盘缓存默认开启）。
- **工具三分离**（#1051–#1067，未定案）：可见/可选/可执行三分离。用户否决软提示（「靠 agent 的不幻觉来输出……可控性降低」#1059）；暂定案——首版公共工具共享前缀、高权限工具用 restrict 真删接受缓存分叉，远期自建推理层做解码级子集约束，缓存与权限分层、优先确定性。见 [open-questions.md](open-questions.md) OQ-13。
- **图工程原则**（#910/#935/#982）：「没有真实需求就不画这条边」，每步只加被当前行为逼出的节点/边；「Agent 是节点，插件和运行时负责边的逻辑」——并由此诊断递归派生缺陷（「一加二跑成一加四」#969：边逻辑被放进节点内）。
- **开发方法论**（#846/#918/#922/#949）：每步最小且可验证；第一步只做四件事——主对话顺畅说话、一个子对话后台跑、结果实时回流、主对话选择说或不说且延迟不明显变差；六阶段里程碑：单子闭环→多子并行不互通→收敛→长期状态→行动（第三层）→动态编排；「全局背景一次说清，执行权限一点一点给」，每轮标注不要顺手实现后续功能。
- **反逢迎人格样本**（#682/#915）：「顺着我说 you are absolutely right……跟那些傻逼有啥差别」「你是不是只会说对对对」——先确认理解再评价，不说正确废话。是 PV-6 的又一来源。

## 第三部分（#1090–#1394，09-17 晚）：架构再解释

主线连贯但收尾反复，用户自评「讲的有点散」；定性为**再解释而非推翻**——「我们没有打破原来的东西，只是换了一种理解」（#1193）、「多个注意力头解决小任务、信息通过图传导，我认为我没有变」（#1377）。

### 核心再解释：从「三层」到「平级反应单元网络」

- 出发点：「我们有一些过度地去把主对话当成了表现层」（#1096）、「一个主对话加 N 个子对话的逻辑是有问题的……大家都是平级的」（#1126）。
- 表达降级为输出之一：「想事不是为了要表达，而是表达只是一种需求」（#1120）。
- 「主」的再定义：主对话只是这一次触发链中离边界最近的节点（#1244/#1249）——外部视角的接触点，非固有层级。
- 与既有文档的关系：事件流闭环、触发器、激活召回等功能语义不变；结构叙事从「表现/思考/执行三层」改为「平级反应单元 + 激活动力学」。正文暂不重写，待 reactive unit 方向验证后统一重构（见 OQ-15）。

### 新概念（记录待验证）

- **最小反应单元（reactive unit）**（#1210–#1334）：「能不能找到在这个体系内的最小 IPO」→ Actor 模型（接收输入、按状态处理、发 0..N 输出）；用户命名确认「reactive unit 可能是重点」。
- **激活扩散动力学**（#1244/#1249）：点亮、加强/衰减、弱则消失、强则扩散；连接强度由历史事件造起来；候选原语集「激活、传播、衰减、派生、回流、收敛」——用户类比作体系的"CRUD"。与 [06-memory.md](06-memory.md) 的激活召回同族。
- **需求驱动的生长机制**（#1314/#1330/#1374）：「定义一个简单的框架，然后让这个框架可生长」「从第一性原理……生长出最终该有的样子，而不是上一个时代老旧的结果……不是想要一个更快的马」；「'我要一个财务 Agent'这类需求本身就是一个触发事件，它应该触发生长，而不是直接映射到预设模块」。
- **种子/发育规则**（#1336–#1343）：种子=少量初始反应元+生长规则+连接方式+外部知识获取能力；真正要找的是发育规则（何时分化/复制/连接/稳定）；「先发育，再学习」是分界线。
- **内源性平衡**（#1379/#1381）：「不害怕它疯长，我害怕它没有理由的复制而没有抑制逻辑」「像自然界的平衡……纳什均衡/博弈论均衡才是真正的稳定点」——图自行判断扩张或收缩，非外部铲除。
- **图作为最终结构**（#1170/#1379）：「和这个模型最贴切的其实就是图」「关系自由度最大、依赖有路径可循」——OQ-10 定方向、引擎仍未定。
- **对话即 trigger**（#1140）：「有人跟他对话了，这也是一个 trigger」——对话入口统一进 [05-triggers.md](05-triggers.md) 的触发体系；「完成-返回包括不返回也是一种返回」（#1189）。

### 挂起事项（对话戛然而止于 #1394）

用户主动收敛后达成临时共识：盯住「reactive unit 作为种子细胞最少需要什么，才能长出事后叫'财务 Agent'的结构」（#1371/#1374）。约定下次直接从此点往下走，不再重新讨论主/子 Agent（#1386）。挂起点：① 种子的最小基因/发育规则；② 内生平衡机制。见 [open-questions.md](open-questions.md) OQ-14。
