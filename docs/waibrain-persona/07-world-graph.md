# 世界图与本体：五原语、可供性与权限

Agent 对外部世界的全部认知存在一张图里。本章定义图的元模型、属性的内外之别、可供性的计算方式，以及"可控性"如何用权限模型落地。

## 本体五原语 ✅（#124、#136）

| 原语 | 含义 |
|---|---|
| Self | Agent 自身，含生存约束（见下节内置属性） |
| Entity | 外部实体（人、组织、账户、设备、文件…） |
| Relation | 实体间关系（边，一等公民） |
| Affordance | 可供性：此刻能对某实体做什么（动态算出，非静态字段） |
| Event | 事件（发生的事，含时间） |

💬 ChatGPT 评价（#136）：这五个原语的组合"主流 Agent 框架尚未完整合在一起"——潜在机会。

## 内置属性 vs 外置属性 ✅（#121、#125）

- 反例引入：野外生存者没有"钱"的概念——"我有多少钱"不是人的固有字段；钱是外部派生工具。
- 内置属性：维持运行必需的资源。例："不能没有 token，就像我不能没有血液"——token 配额之于 Agent 如血氧之于人（外部资源形式，内部生存约束）。
- 外置属性：通过控制外部实体接口关联。例："有多少钱"= 银行账户指针/ID + 一条管理关系，不是 Self 的字段。
- 判别法：内置属性消失则 Agent 无法运行；外置属性消失只是失去某项能力。

## 可供性（Affordance）✅

- 定义：**关系（够不够得着）∩ 能力（会不会用）**，动态算出的可调用方法集合，非静态字段（#148）。
- 学科归属：生态心理学（Gibson）→ UX 设计（#137–#139）。例（#138）：同一杯水，人喝、蚊子产卵——对象相同，可供性因主体而异。
- 四层工程模型（#156）：实体关系 → 动作 → 授权判断 → 有效能力。
- 与 skill 的关系："我会骑车，不等于这辆车骑得动"（#201）——skill 是能力（会不会），可供性是此刻环境的许可（能不能），详见 [08-skills.md](08-skills.md)。

## 可控性与权限 ✅（#149、#156）

- 例：账户冻结——关系还在（账户还是你的），但失去管理可控性。可控性 = 某种权限 + 方法。
- 工程实现：授权模型 ABAC（NIST SP 800-162）/ ReBAC，策略引擎 Cedar / OPA，Google Zanzibar 为先例（对话中检索确认）。
- 关键性质：**关系不丢、能力可收回**——冻结是能力失效，不是关系删除。
- 具体形态开放：对话未指定引擎，见 [open-questions.md](open-questions.md)。

## 图模型 ✅（#159、#162、#166、#171）

- 类型 ≠ 表：节点 + 边 + 类型标签；**边是一等公民，可有属性**。
- 边被需要引用时升级为节点（关系实体化 reification，#183：实体化后方向弱化为"参与"）。
- 元模型很小（实体/关系/属性/状态/事件/规则），"无穷的是类型，不是底层元模型"（#187）。
- Schema 后验：先存事实，类型系统从实例中生长（#171）。
- 三层 schema（#179、#187）：具体实例 → 抽象关系类（本体/Schema 层）→ 边类型。
- 存最小事实（实体、关系、状态、事件），能力由规则实时算出："图是表达关系的视角，规则是算能力的函数"（#162、#166）。
- 选型：图数据库 vs 关系型/NoSQL 皆可，未定（#159；开放问题 OQ-10）。

## 认知存储 vs 世界真实存储 🟡（#204、#208）

- 前提：Agent 拿到的是"它认为的事实，而不是世界的事实"；偏差无法 100% 弥补。
- 高成本验证：有些真值理性上不该去验（手伸油锅试油温）——不做验证，是不确定信息下的决策问题，不是缺陷。
- 落地：**一套存储，带认知标注**——每条外部信息存"值 + 来源 + 时间 + 可信度"（#212，与 [05-triggers.md](05-triggers.md) 推送不可全信同源），维护"我相信的世界"，靠交互反馈修正。
- 例：转账失败十分钟后账户被他人解锁而 Agent 不知——认知与现实脱钩是常态，交互是纠偏机制（#201）。
- 冰雕的火（#204）：认知"火是烫的"须实际摸过才更新——高成本验证缺失导致可供性认知保守，可接受。

## 世界系统性推论 ✅（#520–#524）

为记忆自洽，世界图支持系统性派生：

- 派生实体：为 Agent 生成父母等必然关联实体。
- 关系网卷入：被雇佣即自动卷入同事关系网。
- 双视角诠释：用户给 Agent 开银行账户——"我的角度是充值，他的角度是工资"（同一账户实体，两种关系视角）。
- 建模边界决定共享（#525）：同事是否共享同一组织图，取决于是否放入同一张图。
