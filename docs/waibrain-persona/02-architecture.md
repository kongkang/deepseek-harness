# 三层架构与事件流闭环

## 总览

```
                    用户（语音/文字/硬件事件）
                              │
                              ▼
   ┌──────────────── 事件流（Event Stream）────────────────┐
   │  用户话语 · 外部订阅推送 · 定时心跳 · worker 冒泡结果    │
   └───────┬──────────────────┬──────────────────┬────────┘
           ▼                  ▼                  ▼
   ┌──────────────┐  ┌──────────────────┐  ┌──────────────┐
   │  L1 表现层    │  │  L2 思考层        │  │  L3 执行层    │
   │  说这段话的它  │◄─┤  并行思考线网络    ├─►│  worker 群    │
   │  人设/语气     │  │  （每条=一个在意） │  │ （临时伸出去  │
   │  决定说不说    │  │  维护"为什么做"   │  │   的手）      │
   └──────┬───────┘  └────┬────────┬────┘  └──────┬───────┘
          │               │        │              │ 冒泡
          │      读/写     ▼        ▼ 按需拉        │
          │        ┌─────────────────────┐        │
          └───────►│  共享记忆 + 世界图    │◄───────┘
                   │  流式记忆·世界图·    │
                   │  当前状态层(激活)    │
                   └─────────────────────┘
```

## 各层职责

### L1 表现层 ✅

- 用户唯一直接交互的层，仅一个对话（#272–#276）。
- 维持人设与人格表现：他要保持他的"表演层"（#013）。
- 整合并行分支送回的结论，决定哪些该说、怎么说；自己不做深度思考（语音方案共识 2）。
- 是否说话由表现层自主决定：思考层推送的内容，表现层可以读也可以不说（#021、#272）。
- 主动张嘴的出口：被思考层触发时，即使人没说话也可以开口（#021）。

### L2 思考层 ✅

- 形态是**并行思考线网络**，不是一个单一"层"（#063 修正："不是一个层……应该是并行的一条线"）。每条思考线对应一个持续的"在意"。详见 [03-thinking-threads.md](03-thinking-threads.md)。
- 由用户初始设置关注项启动，之后与表现层共享上下文、并行触发（#272）。
- 维护每件事的"为什么做"（why）；执行层只专注"怎么做"（how）（#038）。
- 管理多个 worker 把事做完；worker 结果冒泡回思考层，由思考层总结，再决定是否推送表现层（#021）。
- 推送不等于说：思考层决定"要不要触发表现层"，表现层决定"说不说"。

### L3 执行层 ✅

- worker 是"临时伸出去的手"，可消失；思考线长期存在（#087）。
- 每个 worker 拿到的是**专注数据**：只为该任务整理的上下文。详见 [04-workers.md](04-workers.md)。
- 是"AI 超过人的地方"（#021）：可以并行、不知疲倦、边界清晰。

### 当前状态层（跨层）✅

新增于 #451/#457：思考脑之前、每轮不清零、缓慢漂移的带权重激活集合——"最近脑子里还热着什么"（对象/概念/目标/未完成事项）。它是自我状态的运行时载体，机制见 [06-memory.md](06-memory.md) 的当前状态层一节。

## 事件流闭环 ✅

完整闭环（#066、#072、#087）：

1. 一切输入先进事件流：用户话语、外部订阅推送、定时心跳、worker 冒泡结果，统一为事件（#087）。
2. 事件激活相关思考线（休眠线可被唤醒）。
3. 思考线按需拉起 worker，worker 在专注数据内执行。
4. worker 完成后结果冒泡到所属思考线。
5. 思考线总结 worker 的事情，判断是否值得推送表现层。
6. 表现层自主决定说不说、怎么说；说了的话进入下一轮事件流。

这个闭环同时回答"主动张嘴"：第 5–6 步不依赖用户在场，触发即可走完全程。

## 关键架构决策

| 编号 | 决策 | 状态 |
|---|---|---|
| ARCH-1 | 一套运行时，多个 session，不起两套系统；语音前置与主对话同进程共享底座，靠 session 隔离 | ✅ 语音方案共识 1 |
| ARCH-2 | 分支产出结构化结论（发现了什么/建议怎么说/置信度/是否影响当前回复），不是原始上下文 | ✅ 语音方案共识 3 |
| ARCH-3 | 慢脑不继承快脑全部输出：用户原始输入全给，快脑说过的话压缩成"用户已听到什么"摘要再给 | ✅ 语音方案共识 4 |
| ARCH-4 | 上下文准入在调用大模型之前由代码决定，不进模型判断（#626） | ✅ |
| ARCH-5 | 兴趣门代码级（静态订阅+场景标签+关键词），不走模型 | ✅ 语音方案共识 5 |
| ARCH-6 | 事件流是唯一输入入口；所有层通过事件解耦 | ✅ #087 |
| ARCH-7 | 表现层可被思考层触发主动说话，触发不等于说 | ✅ #021 |
| ARCH-8 | 语音侧时机由播放时间轴调度（剩余可播时长决定"现在接上"还是"沉淀下次带出"） | ✅ 语音方案 B1 |

## 与现有 1+N 实现的映射

| 三层概念 | 现有实现 | 差距（本需求要补的） |
|---|---|---|
| 表现层 | 主对话（人格配置、整合闪念） | 主动说话出口；说话自主权目前被动等下一轮 |
| 思考线 | 外脑（每轮一次性 fork 分支） | 外脑是临时的；思考线要求常驻、有状态、可休眠唤醒（语音方案风险表已列） |
| worker | 外脑内执行 | 专注数据隔离与按需拉取尚未实现 |
| 冒泡 | 闪念回插（落盘等下轮） | 缺播放时间轴快路（语音方案 B1）与"说不说"自主判断 |
| 事件流 | 消息驱动，无统一事件入口 | 订阅推送/心跳/冒泡统一为事件 |
| 当前状态层 | 无 | 全新 |
| 记忆/世界图 | 无（B3 待做） | 全新 |

## 后续再解释（2026-09-17）🟡

后续对话把「主对话+外脑」再解释为平级反应单元网络（reactive unit + 激活扩散），「主」只是触发链中离边界最近的节点（#1096–#1249）。用户定性为再解释而非推翻（#1193/#1377）：事件流、触发器、激活召回等功能语义不变。是否统一重构本章叙事，见 [open-questions.md](open-questions.md) OQ-16；增量详见 [12-updates.md](12-updates.md) 第三部分。

## 内驱性自闭环 ✅

Agent 听到内容后，具体做这件事是它自己决策的结果：有内驱性、知道做成什么样算满意、满意了才给人反馈（#021）。用原话：「Agent 不是思考我怎么让他满意，而是它自己要做到它自己满意，然后再给人类」。这条约束所有层的行为设计：worker 的验收标准来自 Agent 自己的判断，不是用户即时评价。
