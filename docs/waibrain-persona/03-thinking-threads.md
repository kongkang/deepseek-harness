# 思考线：并行关心、生命周期与睡眠

## 定义

思考线（thinking thread）= 一条长期存在的"在意"（#063：用户修正——不是表现/思考/执行之外的又一个层，而是**并行的一条线**；每增加一个"关心"就开出一条长期思考线程）。最终形态：表现层 + 并行思考网络，每条思考线按需拉 worker + 共享记忆与实时事件流（#066、#072、#087）。

思考线与 worker 的本质区别：**worker 是临时伸出去的手，可以消失；思考线长期存在，可休眠只留状态与记忆指针**（#087）。

## 开线门槛 ✅

开一条新思考线的条件很苛刻，三条同时满足（#091）：

1. 值得持续关心（不是一轮对话能消化的）。
2. 本轮解决不完。
3. 可被未来信息激活（有持续输入源）。

## 生命周期状态机 ✅

```
              开线（三门槛满足）
                   │
                   ▼
   ┌───────► 活跃（active）──────┐
   │ 事件激活/新信息        │ 久无新信息·重复度过高
   │                   ▼
   └──── 唤醒 ◄──── 休眠（dormant）──┐
                     只留状态+记忆指针 │
                                    │
        活跃/休眠 ──── 合并(merge) ──►┐
        活跃/休眠 ──── 结束(end) ────►┴─► 关闭（清理运行态，记忆保留）
```

- 活跃 ↔ 休眠：由事件激活唤醒；久无新信息降频直至休眠（#107）。
- 结束：不再关心，运行态清理，记忆永久保留。
- 合并：两条线关心收敛为同件事时合并，避免重复消耗。

## 自判与全局调度的分工 ✅

- **"还在不在意"由各线自判**（#095）：一条线是否继续存在，由它自己对信息的判断决定，不由外部命令。
- **"给多少算力"由全局注意力调度器裁决**（#095）：算力是全局资源，调度器分配。
- 可以有元思考线，但它**只能分配注意力，不能替别的线决定在不在意**——否则退化为唯一主体（#099）。

## 注意力 = 资源调度 ✅

用户否决了"独立注意力模块"（#627）：Agent 不是人，没有精力生理限制。

- 预算充足：关注一百个事就是一百个并行进程，承担一百份成本。用户订阅付费支撑注意力宽度，反向节省人类注意力。
- 预算不足：才需要缩减、排队、优先级排序，下时段再激活。
- 全局调度器的四个外部边界（#107）：算力上限、久无新信息降频、重复度过高休眠、高优先级抢占。

## 内部自由 ✅

思考线可以分叉、反刍、自生新思考线（#096–#100）："这像是人有时候不自主地反复反刍自己的想法"。不设内部审查，唯一的约束是 PV-8 的外部资源边界。

## 前提变化的送达与"允许浪费" 🟡

对话中有一处张力，最终立场偏用户侧：

- 💬 分析建议（#038）：执行层太专注会漏掉"改变为什么要做"的信息（例：Agent 听到用户要演示产品，自主去检查系统；后来有人随口说"演示取消了"，这句与系统检查无关，但直接改变这件事值不值得继续）。建议信息筛选不能只看"和正在做的内容有没有关"，还要看"有没有改变为什么要做"；思考层维护 why，前提变化信息**强制送达**。
- 🟡 用户立场（#039–#041）：知道取消也可以继续做——如果有挑战、未来可能用到；"人类会浪费，AI 也会浪费"。深思熟虑会沉淀为未来可用的记忆。
- 落地口径（本目录建议）：**强制送达保留**（worker 有权知道前提变化），**强制终止不做**（收到后是否继续由 worker/思考线自主决定）。此口径待评审确认。

## 睡眠与每日 reset ✅

Agent 需要每天晚上的 reset（#104–#106），但"失眠可能性不大——它毕竟是程序，可以控制"（#113）。

睡眠期间做的事（#116）：

1. 停掉所有 worker。
2. Checkpoint 当前运行态。
3. 整理/合并/压缩/去重记忆（详细机制在 [06-memory.md](06-memory.md) 夜间整理一节；技能固化在 [08-skills.md](08-skills.md)）。
4. 重建关联。
5. 次日重选少数思考线唤醒。

约束：**reset 的是运行态，不 reset 记忆与人格**（#116）。

选择夜间的理由：算力便宜 + 用户睡觉、整理时无读写干扰（#255）。

对应研究：Letta 的 sleep-time compute（空闲期独立 agent 重算记忆，见 [research-foundations.md](research-foundations.md)）。
