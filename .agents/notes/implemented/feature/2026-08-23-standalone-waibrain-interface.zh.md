# Agent Note: 独立外脑界面

Status: implemented

[English](2026-08-23-standalone-waibrain-interface.md) | 中文

## Problem

外脑产品模型需要先有一个可观察的界面，才能判断其编排细节。复用现有 DeepSeek Harness Web UI 会让这个实验与另一个产品的导航和对话假设耦合，而纯文本原型则无法说清公开对话、持续脑分支和由分支启动的工作 agent 之间的关系。

## Decision

在 `apps/waibrain/` 下增加一个内部独立界面，不导入现有 Web UI，也不注册为可发布的工作区包。

- 产品层面只展示两层：一个公开主对话和多个内部脑分支。工作 agent 作为所属脑分支的能力，不成为第三个并列栏目。
- 使用同一个角色与脑分支工作区承担创建和后续编辑。角色卡分别描述稳定身份、性格、说话方式、关系场景、开场白、对话示例和主系统提示词；必填身份信息完整前不能创建对话。
- 每个脑分支只有一项职责，并拥有单独展示的系统提示词、模型、思考强度、启用状态和可选的工作 agent 权限。每条用户消息先启动主请求，再并发进入每个已启用脑分支，脑分支只向主对话返回简洁报告。
- 运行中的对话只使用两栏：公开主对话和脑分支右栏。从右栏外挂的新脑分支会立即加入当前系统，并接收后续消息。
- 提供三个聚焦的视图：角色与脑分支编排、带实时脑分支状态的公开对话，以及按起始用户消息对齐的时间轴。时间轴表头和消息行使用同一套栏目栅格，小屏幕则把栏目显示为带标签的卡片。
- 让主对话和每个脑分支在无工具的 `waibrain` preset 下作为相互独立、可持久化的 DSH Session 运行。`session.create.systemPrompt` 把每个人格存入所属 Session header；冷恢复与 fork 会重新安装该值，显式 id 重试不能替换它。
- 仅在完整的 1+N Session 集合创建成功后，才把主对话和脑分支绑定发布到界面。部分创建失败不会在界面留下过期绑定，因此重试时每个栏目都会使用当前人物角色和脑分支配置。
- 从 Host 的 `llm.models` 目录读取可用模型和思考强度。通过 `session.selectModel({ saveAsDefault: false })` 应用各栏目的选择，使界面可以复用已配置提供方，同时不修改部署默认值，也不读取设置文档。
- 把每份已编写的脑分支报告作为注入上下文推入主 Session。`[[silence]]` 保持为内部状态，绝不进入公开 transcript。
- 把工作 agent 权限保留为可见的脑分支配置，但不调用工作 agent。所属分支的触发和报告生命周期形成独立运行时决策前，工作 agent 保持暂缓。
- 展示编写好的脑分支报告和推送状态，不展示原始隐藏推理。脑分支运行时提示词要求报告只包含一条自然语言纯文本，并从这条报告通道排除标记语言、JSON、代码块和 deliverable 载体。界面会在模型输出边界校验该要求；不符合时在同一个脑分支 Session 内请求一次纯文本改写，第二次仍为结构化输出则拒绝推送到主 Session。
- 通过根目录命令复用仓库已安装的 Vite、TypeScript 和 Vitest 工具，但界面源码与现有 Web UI 模块保持独立。

## Consequences

产品逻辑会经过真实 Host、已配置模型适配器、Session 持久化和浏览器传输，同时保持与现有 Web UI 相互独立。基于回放的浏览器测试会覆盖一个主 Session、三个脑分支 Session、动态外挂、四条模型流程、三次报告推送、静默过滤和时间轴对齐，无需实时 API key；界面测试会覆盖部分 Session 创建失败后的重试。提供方身份验证和缓存行为仍属于部署职责，工作 agent 调用保持暂缓。

## Alternatives considered

- **扩展现有 Web UI。** 这样可以更快把原型放入当前壳层，但会继承无关的产品信息架构，让独立产品决策更难被看见。
- **在角色编排前增加单独的初始向导。** 这样会让同一组角色决策分散在两套界面中。角色与脑分支工作区同时承担创建和后续编辑。
- **把工作 agent 建模为第三个顶层界面层。** 这与三种运行时角色一致，但会让临时执行细节与持续脑分支拥有相同的视觉权重。把工作 agent 置于所属脑分支下可以保留操作归属。
- **在界面内继续模拟模型回复。** 这样可以隔离布局行为，但无法验证 Host 路由、Session 持久化或脑分支到主对话的投递。浏览器测试改为使用真实 Host 流程和回放提供方 fixture；已配置部署会使用实际适配器。
