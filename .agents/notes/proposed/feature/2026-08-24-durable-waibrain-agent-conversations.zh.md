# Agent Note: 持久化外脑 Agent 对话

Status: proposed

[English](2026-08-24-durable-waibrain-agent-conversations.md) | 中文

## Problem

既有外脑设计提供了数据驱动的 1+N 运行时，但独立界面把 Agent 列表、外脑开关、Session 绑定和当前所选对话保存在浏览器内存中。刷新页面会重新创建示例角色，而不是恢复用户的 Agent；持久化 DSH Session 也无法还原某条历史消息由哪个 Agent、哪套外脑配置和哪段生命周期产生。

外脑需要一份由 Host 持有的记录，把 Agent 当前配置、用户与该 Agent 的每场对话、每条用户消息实际使用的配置，以及所有外脑结果连接起来。这份记录必须保留既有 1+N 执行模型，不能用浏览器编排器替换它。

## Proposal

增加持久化外脑领域和 Host 端协调器。浏览器成为该领域的客户端：它编辑 Agent 配置、选择对话并渲染持久化状态；协调器负责 Session 创建、并行分发、结果投递、生命周期转换和恢复。

[数据驱动 1+N 决策](../../../../docs/handoff/handoff-2026-08-22-2235-waibrain-dialog.zh.md)及其[回灌行为](../../../../docs/handoff/handoff-2026-08-23-1817-waibrain-continuation.zh.md)继续作为运行时基础。[独立外脑界面](../../implemented/feature/2026-08-23-standalone-waibrain-interface.zh.md)继续作为产品界面，但其浏览器本地图和外脑到主对话的编排移到 Host API 之后。

### Agent 与对话身份

- Agent 是由本地用户拥有的稳定一等身份。其当前记录包含角色表单暴露的全部字段、主模型选择、按顺序排列的外脑定义，以及各外脑当前的启用状态。
- 一场对话同时属于本地用户和一个 Agent。它绑定一个公开主 Session，以及在该对话中创建的内部 Session 或运行；任何结果都不能跨越该对话身份。
- “新对话”保留所选 Agent 及其最新外脑配置，创建新的对话记录和 Session 集合，并保留所有旧对话供以后查看。
- 选择另一个 Agent 时，界面选择该 Agent 自己的配置和对话历史。界面选择发生变化时，对话记录绝不改变归属。

### 并行 1+N 运行时

- 公开主对话是 Talker：Flash、关闭推理、零工具。它维持自然对话并把已接纳的闪念表达出来；它不搜索、不编排，也不进行深度思考。
- 每个已启用外脑都是产品层面的一个 N 分支。一个分支内部可以继续使用既有识别影子和工作 agent 阶段，但这些阶段只是一张卡片和一段挂载生命周期之下的实现细节。
- 接纳一条用户消息时，Talker 和每个已启用分支从同一段已完成对话前缀启动，任何一路都不等待其他路。完成顺序不受约束；Talker 通常更快只是性能属性，不是顺序保证。
- 由协调器执行扇出与关联，不由模型或浏览器 JavaScript 执行。关键词路由继续被否决；每条已接纳用户消息都会让所有已启用分支运行其配置的识别路径。
- 分支完成后的结果按原始对话、用户消息、分支身份和配置版本记录。对话仍开放时，既有第一人称 `【闪念】` follow-up 路径可以唤醒 Talker 自然表达。界面展示状态和简洁结果，绝不展示隐藏思考。
- 来自搜索的表达必须如实说明来源，例如使用“我查了一下”，不能使用“我想起来了”。空结果或失败分支不能阻塞 Talker 或其他分支。

### 对话生命周期

- 浏览器刷新、导航、关闭标签页或客户端连接中断，都不改变任何 Host 进程或对话状态。运行中的主对话和分支工作继续执行，重新连接后加载持久化对话。
- 用户明确执行“关闭对话”时，系统关闭新输入接纳并立即停止主对话。关闭提交后，主对话不再发送任何公开消息。
- 关闭前已经接纳的分支工作继续完成。结果追加到原对话供查看，但不会唤醒已关闭的 Talker，也绝不会进入较新的对话。
- 关闭对话不会创建取消树。已经接纳的分支结算后，由于再无用户消息能够启动新分支，对话自然达到完全停稳。
- 普通外脑开关属于配置变更，不属于关闭对话。它从下一条已接纳用户消息开始生效，不改变当前消息已经接纳的工作。

### 配置版本与动态外脑

- 每次 Agent 变更都会创建新的不可变配置版本。对话记录每条已接纳用户消息使用的版本，时间轴显示编辑、挂载、启用或关闭操作从哪条消息边界开始生效。
- 主人设变更和外脑变更都从下一条用户消息开始生效。历史消息保留原始版本并可重现。
- 新外挂的分支在收到第一条实时消息前取得当前公开对话上下文。完整 transcript 持久化保存；模型上下文在容量允许时使用完整可见历史，超出后使用持久化摘要和近期消息。
- 新对话继承 Agent 最新的外脑列表，以及上一场对话结束时保留的启用状态。外脑状态属于 Agent 的连续能力，不是仅存于浏览器的默认值。
- 未来的自我更新可以根据用户指令创建、编辑、启用、关闭外脑或设置到期时间。包括 24 小时有效期在内的限时外挂使用同一套版本和生命周期模型；自动自我更新不属于第一阶段实现。

### 第一阶段实现范围

- 持久化并恢复 Agent 和外脑表单当前可编辑的每个字段，包括模型、推理选择和外脑开关。
- 通过 Host 持有的 DSH 持久化保存 Agent 列表、对话索引、当前所选对话、Session 绑定、配置版本、生命周期事件、消息和外脑结果。
- 页面刷新和 Host 重启后恢复准确的 Agent 和上次所选对话。只有“新对话”会创建空 transcript。
- 支持创建和选择 Agent、新对话、查看历史对话、动态外挂分支、编辑分支、启用/关闭变更、消息扇出，以及明确关闭对话。
- 复用已注册的 DSH 模型目录、Agent preset、Session 日志、storage-domain 和 Host Remote API。不得创建第二套浏览器持久化模型或私有模型调用协议。
- 本阶段不增加 skill、工具或记忆挂载界面与执行。它们以后的配置属于各自 Agent 或外脑，并扩展同一套稳定身份。

## Alternatives considered

- **把图保留在浏览器内存或 localStorage。** 这种方式无法跨浏览器恢复，无法还原 Host 持有的后台工作，也无法证明哪套配置产生了持久化 Session 轮次。
- **只在 Session header 中保存完整 Agent 图。** Header 是不可变创建元数据，无法在不重写历史的情况下表达多场对话、从下一条消息生效的配置版本、分支生命周期事件或 Agent 当前记录。
- **让独立页面编排各个 Session 调用。** 页面关闭会移除操作所有者，恢复依赖重建 JavaScript 队列，而且实现会偏离既有 Host 端 1+N 运行时。
- **关闭对话时取消所有分支。** 这样会丢失已经接纳的后台工作，并违背自然结算模型。
- **让 Talker 串行先于外脑。** 这样会把延迟差异变成依赖，违反并行 1+N 模型。

## Acceptance criteria

- 创建 Agent、填写当前每个表单字段、增加多个外脑并保存后，Host 产生持久化记录。
- 浏览器刷新和 Host 重启后恢复准确的 Agent 配置、外脑状态、当前所选对话和 transcript，不重新创建 Session。
- “新对话”保留 Agent 和最新外脑状态，创建空 transcript，并让旧对话仍可选择且内容不变。
- 接纳一条用户消息后，Talker 和所有已启用分支都在任何一路允许完成之前启动；测试不对 Talker 先完成作任何断言。
- 关闭、启用、编辑或外挂分支会影响下一条用户消息，时间轴明确标识变更前后各自使用的配置版本。
- 新外挂分支取得所加入对话的派生上下文，不能取得其他对话的上下文或结果。
- 工作运行时关闭浏览器不会取消任何 Host 工作；重新打开后可以看到完成结果。
- 明确关闭一场对话会阻止新输入和此后的所有主对话公开回复，同时允许已经接纳的分支完成并把结果记录在同一场对话中。
- 一个分支失败或超时会被记录，但不阻塞 Talker 或其他分支。
- 无密钥单元测试、真实组合测试、Session 日志 snapshot 和浏览器测试证明持久化、恢复、并行接纳、关闭竞态和跨对话隔离；另用已配置真实提供方的冒烟测试验证组装后的模型路径。

## Risks

- Agent 领域写入和 Session 日志追加在崩溃时可能分离，因此每个操作都需要一个明确提交点和幂等恢复流程。
- 关闭、结果投递、配置更新和新消息接纳可能发生竞态；协调器需要按对话串行化操作并使用明确的接纳快照。
- 不限制外脑数量可能耗尽模型提供方或 Host 资源。产品配置不设固定卡片上限，但部署需要控制并发、超时和保留数据大小，并在越界时明确失败。
- 如果模型可见的配置或结果输入没有对应 Session 事件，恢复后的历史会与原始请求不同。所有模型可见输入都必须能从日志重建。
- 现有独立 Demo Session 没有持久化 Agent 图。它们仍可作为 Session 查看，但第一阶段不推断或迁移从未持久化的浏览器配置。
