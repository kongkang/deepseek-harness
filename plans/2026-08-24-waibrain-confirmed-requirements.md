# 外脑对话：已确认需求

## 产品目标

用户与一个主 Agent 持续对话，多个外挂外脑在后台独立工作，为主对话提供信息和思路。网页只负责配置、操作和展示，实际运行必须复用 DeepSeek Harness 的标准 Host 流程，不能由浏览器临时编排另一套运行逻辑。

## Agent 与数据

- Agent 是稳定身份，不会因为新建对话而更换。
- Agent 配置必须持久化。第一阶段保存当前表单中的全部字段，包括名字、提示词、模型和外脑配置。
- 对话属于当前用户和当前 Agent。更换 Agent 后，应看到该用户与另一个 Agent 的对话记录。
- 每场对话必须保留当时使用的 Agent 配置、外脑列表、开关状态及其变更时间，历史记录不能被后续配置覆盖。
- 页面刷新或 Host 重启后，Agent 配置、当前对话、消息和外脑状态都必须恢复。

## 主对话与外脑

- 主对话只负责自然交流，不承担搜索、深度思考或外脑编排。
- 每个外脑是依附于主对话的独立分支，输入来自该主对话，结果只回到触发它的原对话。
- 用户发送一条消息后，主对话和所有已启用外脑从同一段已完成历史并行启动。任何一路都不等待其他路，也不保证谁先完成。
- 外脑失败、超时或没有结果，不能阻塞主对话和其他外脑。
- 外脑结果可以回填并帮助主对话继续表达，但不能跨到另一场对话。

## 外脑管理

- 一个 Agent 可以挂载任意数量的外脑；实现可以设置部署级并发限制，但产品数据不能写死为固定数量。
- 每个外脑都有独立开关，可以随时启用或关闭。
- 对话过程中可以新增或修改外脑；新增、修改和开关变化统一从下一条用户消息开始生效。
- 新增外脑首次运行时读取当前主对话的历史；上下文过长时使用已有的摘要与近期消息机制。
- 新对话默认继承该 Agent 最新的外脑列表和上一场对话结束时的开关状态。

## 新对话、刷新与关闭

- “新对话”只创建一份新的聊天记录，不更换 Agent。旧对话永久保留并可随时查看。
- 用户没有点击“新对话”时，刷新页面必须回到上次所选对话。
- 关闭网页、刷新、断网或重新连接都不能改变 Host 中正在运行的工作。
- 用户主动关闭一场对话后，系统立即停止接收新消息，主对话不再向用户发送任何新内容。
- 关闭前已经启动的外脑不取消；它们完成后仍把结果记录到原对话，但不能再唤醒主对话。
- 旧对话的迟到结果绝不能进入后来创建或打开的新对话。

## 第一阶段范围

第一阶段只保证第一个页面可用：创建和选择 Agent、保存并恢复表单、管理外脑及开关、新建和恢复对话、并行发送、查看历史以及主动关闭对话。

Skill、Tools、Memory、自我更新和限时外脑属于后续能力。本阶段不实现这些运行功能，也不为它们提前增加复杂界面。

## 第一阶段完成标准

1. 用户能在第一个 Tab 创建 Agent，填写配置并保存。
2. 刷新页面和重启 Host 后，完整配置和上次对话原样恢复。
3. 用户能新增多个外脑，保存配置，并随时切换各自开关。
4. 新对话沿用同一个 Agent 和最新外脑状态，旧对话仍可查看。
5. 每条消息让主对话和全部已启用外脑真正并行运行。
6. 页面关闭不影响后台工作；主动关闭对话符合上述停止与回填规则。
7. 浏览器端到端测试覆盖以上操作，并使用真实 Host 组合而不是浏览器内存假数据。
