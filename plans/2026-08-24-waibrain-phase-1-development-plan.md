# 外脑网页第一阶段开发计划

## 目标

按照[已确认需求](2026-08-24-waibrain-confirmed-requirements.md)，先让外脑网页第一个 Tab 真正可用：Agent 和对话由 Host 持久化，刷新后可以恢复，外脑可以动态配置，主对话与外脑按照既有 1+N 流程并行运行。

## 实施原则

- 复用 DeepSeek Harness 已有的 Agent、Session、事件日志、持久化、模型和 Host API。
- 浏览器只保存未提交的表单草稿，不能成为 Agent、对话或运行状态的真源。
- 先完成第一阶段验收，不实现 Skill、Tools、Memory、自我更新和公开网络部署。
- 先写能失败的测试，再实现对应功能。

## 开发步骤

### 1. 固定测试场景

先为以下行为建立自动化测试：

- Agent 全部表单字段保存和读取。
- 刷新页面和重启 Host 后恢复同一 Agent、同一对话和原有消息。
- 新对话不更换 Agent，继承外脑状态，旧对话仍可查看。
- 外脑新增、编辑和开关从下一条消息生效。
- 主对话和全部已启用外脑并行启动。
- 页面关闭不取消后台工作。
- 主动关闭对话只停止主回复和新输入，已启动外脑继续完成并写回原对话。
- 迟到结果不能进入另一场对话。

### 2. 保存 Agent 配置

- 在 Host 中增加 Agent 配置的创建、读取、更新和列表能力。
- 保存当前表单全部字段、主模型、外脑顺序、各外脑配置和开关。
- 每次修改生成新的配置版本；已经接收的消息继续使用旧版本，下一条消息使用新版本。
- 使用现有持久化能力保存数据；第一阶段本地默认实现可以使用 SQLite 或现有 storage provider。

### 3. 保存对话和恢复状态

- 每场对话绑定一个 Agent 和一个主 Session。
- 保存对话列表、当前所选对话、开放或关闭状态以及外脑运行记录。
- 页面启动时读取 Host 状态，不再自动创建示例 Agent 或空对话。
- “新对话”创建新 Session；普通刷新只恢复，绝不新建。

### 4. 接入既有 1+N 运行流程

- 把网页当前的浏览器端外脑编排移到 Host。
- 用户消息被接收时，冻结本轮 Agent 配置版本和已启用外脑集合。
- 主对话与所有已启用外脑从同一历史前缀并行启动，不设置主对话优先或外脑之间的全局等待。
- 每个外脑独立记录开始、完成、失败或超时，结果始终绑定原始对话和原始消息。
- 对话仍开放时，外脑结果可以通过既有回灌路径帮助主对话表达；对话已关闭时只保存结果。

### 5. 改造第一个 Tab

- 增加 Agent 新建、选择和保存。
- 所有现有表单字段都从 Host 读取并写回 Host。
- 外脑卡片支持新增、编辑、启用和关闭。
- 增加历史对话选择、“新对话”和“关闭对话”。
- 明确显示保存失败、加载失败、运行中、已关闭和外脑失败状态。

### 6. 完成真实端到端验收

使用真实 Host 和浏览器依次验证：

1. 创建 Agent，填写全部字段并增加多个外脑。
2. 保存后刷新页面，确认配置、开关和对话不丢失。
3. 重启 Host，再次确认恢复结果。
4. 发送消息，确认主对话和所有已启用外脑均已启动。
5. 在对话中关闭、修改和新增外脑，确认下一条消息使用新配置。
6. 新建对话，确认 Agent 不变、外脑状态继承、旧记录可返回查看。
7. 外脑运行时关闭网页，重新打开后确认后台结果已经写回。
8. 主动关闭对话，确认主回复停止、外脑自然完成、结果不串到新对话。

## 交付顺序

1. Host 持久化和 API。
2. 对话恢复和配置版本。
3. Host 端并行 1+N 编排。
4. 第一个 Tab 接入真实数据。
5. 浏览器端到端测试和真实模型冒烟测试。

只有上述端到端场景全部通过，才能说第一阶段“网页可用”。单元测试、构建通过或页面能打开，都不能替代真实浏览器验收。
